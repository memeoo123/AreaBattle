# 工具路由与生产接口

## 工具发现

先查看当前可调用工具及项目已安装工具，不凭产品名推断可自动操作。工具名以当前 schema 为准。缺少可选软件不阻止盘点和方案；缺少运行环境时不能把静态检查写成运行通过。

| 工作 | 优先调用 | 产出与边界 |
|---|---|---|
| 项目盘点 | exec_command：rg、文件读取、git status/diff | 有文件证据的资源链，读取范围限相关项目 |
| 查看本地画面 | view_image | 检查真实素材与截图；不用记忆替代观察 |
| 新建或编辑位图 | 可用的 imagegen skill 与 image_gen 工具 | 概念图、图片素材、透明切图；不能直接产出可用骨骼/FBX |
| 简单代码图形 | 原有矢量/网格/UI/Shader 编辑工具 | 连线、选中框、射程圈等参数驱动图形 |
| 文件与代码接入 | apply_patch、项目编辑器脚本 | 可审查差异、资源配置与导入 |
| Unity 操作 | 发现实际可用 Unity MCP；否则已有编辑器脚本/CLI | 导入、编译、场景运行、截图；没有工具则明确缺口 |
| 3D建模/离线渲染 | 确认可用的 Blender CLI/脚本或用户建模流程 | 模型、材质、固定镜头渲染图；未安装不自动假装已完成 |
| Spine 制作 | 确认可用编辑器及相容的导出流程 | 骨骼、图集、动作；运行库不是创作编辑器 |
| 展示交付 | 本地图片内联、文件链接、open_in_codex（若有） | 展示实际产出，区分概念预览与引擎截图 |

仅在需要最新格式兼容、软件能力、费用或外部参考时查官方文档；项目事实以本地证据为准。不要为已有能力额外要求订阅第三方AI。商业软件安装、API付费路径和账号连接不能默认为已具备。

## ImageGen 调用约定

实际图像生产时先读取当前 imagegen skill（若可用），遵守实时工具 schema；这里的示例不是冻结的 API 定义。

1. 本地图片先用 view_image 查看，明确哪些是待编辑对象，哪些只提供风格或构图参考。
2. 默认使用内置生成工具。新图不附不存在的参考；有本地参考时使用 schema 提供的本地路径参数，否则按 schema 使用最近会话图片参数，两种方式不要混用。
3. 透明素材设置 `transparent_background: true`；背景图或完整场景效果图设为 false。
4. 提示词说明逻辑用途、参考角色、选定风格、镜头/光照、对象轮廓、留白与锚点要求、透明度以及必须保留的部分。不要声称提示词中的尺寸要求等于实际文件尺寸保证。
5. 用当前工具要求的方式等待并显示图片（代码工具可用时使用 generatedImage 返回结果）。生成耗时不意味着已失败，不重复提交同一请求。
6. 项目用图复制到项目的风格资源目录，检查实际文件及导入结果；预览图可保持预览用途。保存提示词及输出映射。
7. AI图像编辑继续使用图像工具；不要静默改用脚本重绘/抠图。元数据、哈希、尺寸与透明通道检查可用文件工具。资源变换遵守当前工具规则和用户授权。
8. 内置生成不可用时说明受阻项，继续可独立完成的规格工作。不要擅自切到外部付费 API；用户选择 CLI/API 后再遵循其工作流。

生产提示词示例，实际填写已有风格约定：

> 用途：塔防游戏基础塔单体素材。参考一用于形状与光照，参考二仅用于占屏比例。保持已选风格、镜头角度与光照方向；完整塔体，底部接地点清楚，留透明边距。阵营区域与主体材质分明，小尺寸可辨认。真实透明背景，无地面、数字、文字标签或界面。与同系列塔保持共同基座和比例。

要求后续构图严格保留时，说明哪些位置必须不变，并在结果中逐项检查；生成工具不能代替像素精确的验证。

## 动画路径选择

- **静态 Sprite**：生成独立图片后接入；程序动画可补弹跳/受击，但不能宣称已有走路骨骼动画。
- **实时 Spine**：需要可编辑的分层部件、骨骼绑定、动作与图集。检查项目运行库和导出版本。仅换贴图时确认部件布局/UV兼容；不兼容就重新制作与导出。
- **烘焙顶点动画**：检查网格、UV/顶点索引、动画纹理、解码Shader、时间参数。外形/拓扑变化通常需要重新烘焙整套匹配数据。现有 importer 不一定是可供新角色使用的 baker；先验证源资产和烘焙工具。无法重烘焙时可提出改为 Spine/序列帧等方案，说明性能和工程影响，不自动悄悄替换。
- **序列帧**：每帧需要一致轮廓、锚点、尺寸与周期；逐帧生成须检查抖动和形变，不保证AI自动保持一致。
- **真实3D**：需要模型、材质、必要的骨骼动画与导出配置。确认用户是否要改变运行时表现；“3D质感”也可以由固定视角2D渲染实现。

批量前先打通一个完整对象：源资产 → 导出 → 导入 → 状态播放 → 回收。大量士兵需要实测，不把实时骨骼或大量独立材质默认视为低成本。
